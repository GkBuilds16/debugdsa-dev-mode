# Testing

Run backend tests from the root with `npm test`, frontend component tests with `npm run test -w frontend`, and compile the frontend with `npm run build`. Backend API tests use mocked Mongoose model calls and an ephemeral HTTP server. Post Codebase service tests cover validation, unsafe ZIP entries, storage-key isolation, and GitHub URL policy. Candidate tests cover public serialization, workspace validation, schema indexes, stale and concurrent revision conflicts, failed-write storage cleanup, snapshot immutability, cross-candidate workspace/submission access, authentication for each candidate API group, published-version and archived-challenge checks, discovery filters, bookmark duplicate handling, candidate editor autosave/reset/recovery/submission, and API errors. Battle tests cover schema/index definitions, allowlisted config, server-clock lifecycle boundaries, conditional capacity query/duplicate rollback, stale workspace cleanup, immutable battle snapshots, and disabled evaluation. UI tests cover battle discovery filters, registration/lobby state, service errors, candidate autosave/reset/recovery, and submissions. These tests do not constitute MongoDB integration, real concurrent database writes, browser end-to-end verification, or a complete visual/manual UI audit.

MongoDB-backed tests are still required for unique-index enforcement, simultaneous capacity reservations, registration/count recovery, atomic workspace updates, snapshot lifecycle, stale bookmarks, and active-workspace creation races. Add ZIP upload route integration and browser end-to-end flows. The current environment has no verified MongoDB service, so database integration tests were not run. Component tests use mocked API responses; browser authentication with the platform token provider and the battle scheduler against a running server have not been exercised.

`backend/src/crossModule.test.js` adds a mock-backed regression from persisted Post Codebase source objects through candidate attempt/submission services and battle version binding/workspace opening. It exercises local filesystem object reads/writes but does not verify HTTP workflow orchestration or MongoDB. See [verification-matrix.md](verification-matrix.md) for the full evidence boundary.
