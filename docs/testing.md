# Testing

Run backend tests from the root with `npm test`, frontend component tests with `npm run test -w frontend`, and compile the frontend with `npm run build`. Backend API tests use mocked Mongoose model calls and an ephemeral HTTP server. Post Codebase service tests cover validation, unsafe ZIP entries, storage-key isolation, and GitHub URL policy. Candidate tests cover public serialization, workspace validation, schema indexes, stale and concurrent revision conflicts, failed-write storage cleanup, snapshot immutability, cross-candidate workspace/submission access, authentication for each candidate API group, published-version and archived-challenge checks, discovery filters, bookmark duplicate handling, candidate editor autosave/reset/recovery/submission, and API errors. These tests do not constitute MongoDB integration, real concurrent database writes, browser end-to-end verification, or a complete visual/manual UI audit.

MongoDB-backed tests are still required for unique-index enforcement, atomic concurrent workspace updates, snapshot lifecycle, stale bookmarks, and active-workspace creation races. Add ZIP upload route integration and browser end-to-end flows. The current environment has no verified MongoDB service, so database integration tests were not run. Component tests use mocked API responses; browser authentication with the platform token provider has not been exercised.
